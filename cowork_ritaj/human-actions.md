## H1 · Protect the `release` branch (T1.5)

`GET /repos/MohAwwad04/NLP_Project/branches/release/protection` returned **404**
on 2026-08-10 — the branch is unprotected, so "reviewed release commit" is
currently a convention, not a control. Anyone with write access can push
straight to it.

**Who:** the repository administrator. **Unblocks:** Stream 7 (cutting the
release candidate).

```bash
gh api -X PUT repos/MohAwwad04/NLP_Project/branches/release/protection \
  -H "Accept: application/vnd.github+json" \
  -F "required_status_checks[strict]=true" \
  -F "required_status_checks[contexts][]=Backend tests" \
  -F "required_status_checks[contexts][]=Corpus, navigation, privacy and extension policy" \
  -F "required_status_checks[contexts][]=Secrets and dependencies" \
  -F "required_status_checks[contexts][]=Portal build and extension tests" \
  -F "required_status_checks[contexts][]=Load and resilience" \
  -F "required_pull_request_reviews[required_approving_review_count]=1" \
  -F "enforce_admins=true" -F "restrictions=null"
```

The context strings are the **job names** in `.github/workflows/ci.yml`; if a job
is renamed, this list must be updated or the required check silently never
reports. `enforce_admins=true` is deliberate — a rule the admin can bypass is a
rule that gets bypassed at 1am.

**Verify:** the same endpoint returns 200 and lists those five contexts.

```bash
gh api repos/MohAwwad04/NLP_Project/branches/release/protection | jq '.required_status_checks.contexts'
```

## H2 · Rotate the operator passwords (T1.4)

`ritaj_rag_admins.rtf` holds weak, username-derived plaintext passwords. Treat
them as already disclosed. The file is gitignored, which prevents publication —
it does not undo disclosure.

**Who:** a maintainer, at a real terminal. **Unblocks:** release checklist §E.

**Passwords must never be generated by an agent, pasted into a chat, or passed
as a command-line argument.** `python -m ritaj.adminauth hash <username>` prompts
interactively for exactly this reason: the password never enters `argv`, shell
history, or a transcript.

1. Generate new passwords in a password manager (one per operator).
2. For each account, in a real terminal:
   ```bash
   python -m ritaj.adminauth hash <username>     # prompts; prints username:bcrypt_hash
   ```
   or, for a full set at once:
   ```bash
   python scripts/set_admins.py --count 3
   ```
3. Set `ADMIN_USERS` on the host to the resulting pairs, and roll
   `SESSION_SECRET` at the same time — an old signing key keeps old sessions
   valid.
4. Delete `ritaj_rag_admins.rtf` from every machine that has it.
5. Confirm:
   ```bash
   python scripts/secret_inventory.py     # ADMIN_USERS present, fingerprint changed
   test ! -f ritaj_rag_admins.rtf && echo "plaintext file gone"
   ```

Setting `ADMIN_USERS` makes the legacy shared `ADMIN_TOKEN` stop working, which
is the intended outcome. Rotation is documented in `docs/OPERATIONS.md` §3.5.

## H4 · Approve navigation destinations (T5.1)

All five actions in `data/navigation.yaml` are `enabled: false` with an empty
`approved_by`, so the flagship navigation feature resolves nothing today.

**Who:** a Ritaj service owner decides; an agent applies the edit.
**Unblocks:** T5.2 shot 3, and the feature itself.

Set `enabled: true` and `approved_by: <named person or ticket>` **together**,
one action per commit. Setting `enabled` without an approver is the failure mode
`navigation.problems()` exists to catch — such a row is dropped from the
registry at load, so it looks approved in the file and does nothing in the
product.

**Verify:**
```bash
python scripts/check_navigation.py        # zero awaiting approval, 18/18 hostile URLs rejected
node --test chrome-extension/navigation.test.mjs
```
